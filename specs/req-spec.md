# MyDay Web App
- 一款每日计划 Web 应用，帮助用户以个性化推荐开启每一天
- 只服务中国大陆，只用高德。不配置 Google Maps。接口见 `specs/tech-spec.md`
- 浏览器定位和手输地点都先确认在中国大陆。不在中国大陆时提示「高德地图不支持这个地点」，留在 page 3，不开始运势和天气。出生城市不在中国大陆时同样提示，两路都不开始
- 界面仅中文

## 概述
- 入口页面：page 1 「档案列表」：展示已有档案卡片列表
- page 2 「新建档案」：用户填写个人信息并保存为个人档案
- page 3 「规划我的一天」：用户提供今日心情和做什么，获取用户位置（自动获取；定位失败时手输城市）。位置可用后，点击「规划我的一天」才同时获得「当日运势」和「当日天气」
- page 4 「我的今日计划」：展示 page 3 获得的「当日运势」和「当日天气」。生成今日穿搭文字和真人穿搭图。按 page 3 的位置，用户输入菜系后列出附近餐厅

## 需求规格

### page 1 档案列表
- 以网格视图展示所有现有档案
- 每个档案以卡片形式展示，包含姓名与照片
- 点击档案卡片，加载该档案的信息后进入 page 3「规划我的一天」
- 点击「新建档案」按钮进入 page 2「新建档案」页面

### page 2 新建档案
- 用户填写个人信息
  - 姓名（必填）
  - 出生城市（必填）。填写一个城市，例如「上海」
  - 出生日期（必填）
  - 上传个人照片（必填）
- 点击「保存」按钮保存档案。姓名、出生城市、出生日期或照片未填时，不保存，留在 page 2，并标出未填项。保存成功后回到 page 1「档案列表」，新档案出现在列表中


### page 3 规划我的一天

用户在本页确认档案、输入当前状态。

#### 「我的档案」区域：
- 展示当前档案的姓名与照片。不在本页编辑或删除
#### 「我现在的状态」区域：
- 获取当前位置（默认使用浏览器定位）。定位失败时，须手动输入城市/商圈
- 手输城市先变成可用位置。这段不计入后面两路的等待。无法变成可用位置时，留在本页并说明需要重填。点击不开始两路
- 位置仍无效时，不开始「当日运势」和「当日天气」，也不进入 page 4
- 用户手动输入「我现在的心情」，如「兴奋」
- 用户手动输入「我今天在做什么」，如「旅行」
- 位置可用之后，用户方可点击「规划我的一天」，否则按钮不能点击
- 点击按钮「规划我的一天」，进入「规划我的一天：取数」。
#### 「规划我的一天：取数」
- 本部分是用户从「我现在的状态」点击按钮「规划我的一天」后的操作，界面停留在 page 3
- 只展示进度提示，不展示「当日运势」和「当日天气」的内容，这两部分内容在 page 4 展示
- 星盘和天气同时开始。对话等星盘返回后再开始，不等天气。得到「当日运势」和「当日天气」。
- 星盘和天气都开始后一起等待。不要等星盘结束再开始天气，也不要等天气结束再开始星盘。
##### 「当日运势」：结合星座、「我现在的心情」和「我今天在做什么」，生成「当日运势」
- 包含「今日宜做 / 今日不宜」以及其他趣味建议。
- 星盘的位置用档案里的出生城市，不用当前定位。出生城市无法使用时，留在本页，说明需要修改出生城市，两路都不开始。这段不计入两路的等待。运势文字用对话生成。
##### 「当日天气」：按当前位置取得「当日天气」。当前位置只用于天气和餐厅
##### 失败
- 等待时只显示一句「正在为您的一天生成洞察」
- 两路里有一路失败时，留在本页并说明原因。不要进入 page 4。不提供重试。
##### 「当日运势」和「当日天气」都成功后，进入 page 4「我的今日计划」

### page 4 我的今日计划

天气区域和星座区域直接展示 page 3 已经取到的数据，不再发起那两路请求，也不显示「正在为您的一天生成洞察」。穿搭文字和穿搭图同时开始。一块失败时只说明这一块。不提供重试。

#### 顶部区域
- 「你好，{姓名}」 + 照片
- 展示个人信息，包括年龄，以及由出生日期算出的星座名
#### 天气区域
- 展示 page 3 取得的「当日天气」
- 天气描述先变成中文再展示给用户
#### 星座洞察区域
- 只展示 page 3 取得的「当日运势」。其中已包含「今日宜做 / 今日不宜」和其他趣味建议

#### 穿搭推荐区域
使用 page 3 已经取到的「当日天气」「当日运势」，以及「我现在的心情」「我今天在做什么」。下面两块同时开始，一块不需要等另一块结束。
- 「穿搭推荐文本」：生成穿搭推荐，以文字展示
- 「真人穿搭生图」：生成今日穿搭的人像图。用档案中的照片作为本人形象，生成高度写实虚拟形象。读不到照片时要报错。禁止改成不使用照片的图

#### 展示**今日吃什么**推荐：
##### 用户输入菜系
- 用户输入菜系文字。未输入时不查找
- 用 page 3 已经得到的位置，按 `specs/tech-spec.md` 的「周边餐饮检索」查找，范围 3 公里，半径不扩大。page 4 不再获取定位
- 以列表形式展示结果，按距离排序。
- 每条展示餐厅名称、距离、地址。不展示评分、评论数或点评摘要
- 点击餐厅后弹出浮层，展示餐厅详细信息，并打开该地区的地图，显示位置及导航。支持关闭、Escape、点击背景关闭
- 无结果情况处理：
  - 须说明原因：可换菜系，或返回 page 3 重选位置。
  - page 4 不在本页改位置。返回 page 3 后，位置改好并再次点击「规划我的一天」，才按上面的规则重新取得天气和运势。
  - 之前的 page 4 结果不再使用。禁止空白列表


### 测试

- 每一页一条测试，用夹具，不出网
- page 1：点击档案卡片进入 page 3
- page 2：缺姓名不保存
- page 3：两路都成功才进入 page 4
- page 4：展示已取到的天气；未输入菜系不查找

### 验收测试

按下面的路径开发。上一步能走通，再写下一步。

四条夹具测试通过后，执行 `npm run dev`。在浏览器里只走一遍下面的路径。走通后，在回复里给出本地地址，然后停止。

- 打开档案列表。进入新建档案，不填任何项就点「保存」。页面留在新建档案，并标出姓名、出生城市、出生日期、照片未填。
- 建一条档案。文件选择框无法上传时，用接口写入一张小 PNG 再建档，然后继续后面的步骤。不要为此改上传实现。
- 打开该档案的「规划我的一天」。页面没有报错。没有地点时，「规划我的一天」不能点击。
- 手输一个中国大陆城市。按钮可以点击后，点击一次「规划我的一天」。
- 「我的今日计划」能看到天气、运势、穿搭文字和穿搭图。未输入菜系时不查找。输入一次菜系后出现餐厅列表。打开一行，按 Escape 关闭浮层。
- 开发模式下穿搭文字和图各请求两次时，保持现状。不要为此改代码。
- 这一遍走通后停止。不再改布局，不再为了再次输入城市而改页面。只有这一遍里改了代码时，才再跑那四条夹具测试。

### 非功能需求
- 本项目用到的能力：对话、图像、天气、星座、高德。不配置 Google Maps。不用宝可梦，也不用路线查询。
- 本项目这次安装：Next.js、React、TypeScript、Tailwind，以及测试用到的 Vitest。数据放在 `data/`。不安装 React Query、Zustand、RHF、Playwright。

## 界面规范

语气：干净、随意、有趣。像一张用来安排这一天的浅色书桌，不是密密麻麻的仪表盘，也不是营销落地页。

### 视觉方向
- 色板（CSS 变量）：Paper `#F7F9FC`、Mist `#E8F1F8`、Ink `#1B2430`、Soft slate `#5B6B7C`、Sun `#F4A261`（主按钮和进度）、Fresh `#2BB673`（只用于成功）
- 背景用浅的天色到纸色，或很淡的纹理。不要整页单一平色，也不要用大面积紫、霓虹或默认暗色
- 问候和分区标题用有识别度的展示字体，例如 Outfit 或相近的几何、亲切的字体。正文和表单用清晰的无衬线。品牌字体不用 Inter、Roboto、Arial 或系统界面字体栈
- 内容页是单列、通栏的分区卡片，从上到下排列
  每张卡片能看出类别：边框加浅色，天气用天色，星座用星色，穿搭用日色，餐饮用叶色。页面是分区卡片，不是一整块不分段的文字
  档案列表：品牌、一句短提示、档案卡片网格、主操作「新建档案」
  今日计划的几类内容不要排成多列瀑布或仪表盘网格
- 档案选择只用姓名和照片的网格
- 餐饮区是竖列表：每行餐厅名称、距离、地址。不展示评分或点评。不要排成多列卡片
- 动效只留两三处：内容出现、按钮按下、浮层开关。尊重 `prefers-reduced-motion`
- 各分区卡片各自出现，并带简短进度。不要整页只有一个转圈。page 3 等待时仍只显示「正在为您的一天生成洞察」

### 页面分区

每个页面由分区卡片从上到下排成一列。每张卡片只有一个用途、一个标题，以及自己的等待、空、失败状态。

| 页面 | 分区（从上到下） |
| --- | --- |
| 档案列表 | 顶部 · 档案卡片网格 · 新建档案 |
| 新建档案 | 顶部 · 档案表单 · 保存 |
| 规划我的一天 | 顶部 · 我的档案 · 我现在的状态 · 规划我的一天 |
| 我的今日计划 | 顶部 · 天气 · 星座洞察 · 穿搭推荐 · 今日吃什么。每一块都是通栏分区卡片，并有自己的色调 |

### 操作与文案
- 主操作用和结果一致的动词。例如「保存」之后能看出已保存，「规划我的一天」进入今日计划
- 空、等待、失败都说明下一步。不显示「超时」。失败的区域只显示自己的说明
- 界面写中文。这次不增加第二种语言
- 键盘：焦点可见。Escape 或点击背景关闭浮层。状态不只靠颜色
- 桌面和手机：控件不被裁切。餐厅行保持整行可扫读，不要改成餐厅卡片网格
