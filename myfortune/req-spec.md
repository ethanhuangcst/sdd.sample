# MyFortune 需求规格

- MyFortune 是一款用星座、塔罗、八字为个人规划提供参考建议的 Web 应用。
- 数据来自三个免费服务：Pandorium 星座 MCP、tarotoo 塔罗 MCP、`@openfate/bazi-mcp` 八字 MCP。接入细节见 `tech-spec.md`。
- 城市到坐标与时区的换算用 Open-Meteo 城市地理编码，无需密钥。

## 功能

### 输入页「你的信息」

- 页面收集四个字段，全部必填：
  - 称呼：用于问候与提示词，1 到 20 个字符
  - 性别：男 / 女（八字大运排法需要）
  - 出生日期：公历，日期不能晚于今天
  - 出生时刻：时:分。八字排时柱必需；不提供「不记得」选项
  - 出生城市：用户输入城市名，每停止输入即调用一次城市地理编码，展示候选列表（「名称 · 省份 · 国家」），用户点选一条；选中后自动获得经纬度与 IANA 时区，不展示坐标数字
- 有任一项未满足时，「开始分析」按钮为灰色且不可点击
- 没有候选结果时提示「未找到城市，试试更完整的名称」

### 分析页「今日指引」

- 点击「开始分析」后，三个 MCP 同时调用、互不等待：星座（`calculate_natal_chart`）、塔罗（`draw_cards` 抽 3 张、允许逆位）、八字（`calculate_bazi_chart`）
- 一块返回就先渲染一块：星盘摘要区、塔罗牌面区（三张卡：牌名、正逆位、关键词）、八字摘要区
- 三路全部成功后，调用 LLM 生成一段洞察分析；任一路失败时该路显示失败原因、其余两路照常展示，洞察不开始；用户可手动再试失败的那一路，不自动重试
- 洞察下方提供三个折叠区，展示三路 MCP 的原始结果摘要，并与 LLM 输出明确区分

### 洞察提示词

输入：三路 MCP 的结构化结果、称呼、性别。

```text
你是命理与塔罗顾问。只根据下面三个数据源的事实，写一段中文建议，150 到 250 字。
结构：先用一两句各概括星盘、八字、塔罗给出的信息，再给一条结合三源的具体建议。
只使用数据源中出现的信息，不要编造牌面、干支、星象或数据源没有的事实。
语气平和，开头不要问候。结尾说明这是传统命理与塔罗框架下的参考，仅供娱乐与自省。
星盘：{星盘结果}
八字：{八字结果}
塔罗（本次抽牌）：{塔罗结果}
用户：{称呼}，{性别}
```

### 一问一答

- 入口在分析页下方，输入框常驻。占位提示语：「输入你想问的问题，例如：我明年适合换工作吗？」
- 用户提交问题后：重新抽一次塔罗（每问一抽）；星盘与八字复用本次会话已得到的结果，不重复调用（同一出生信息的命盘不变，且星象服务有限流）
- LLM 回答为一段中文，100 到 200 字；结合本次牌面与既有命盘数据作答；区分「命盘/牌面事实」与「AI 解读」；不编造数据源没有的内容
- 历史问答保留在会话上下文中，回答要参考用户问过什么
- 每次回答后输入框清空并保持可输入；正在回答时显示等待状态，失败只说明该次回答失败，可重新提问
- 界面禁止出现「超时」字样

### 问答提示词

输入：星盘结果、八字结果、本次塔罗牌面、历史问答摘要、用户问题。

```text
你是命理与塔罗顾问。用户会围绕自己的规划提问。只根据下面的既有数据与本次塔罗牌面回答，一段中文，100 到 200 字。
结构：先点出与问题相关的牌面或命盘事实，再给一条可执行的小建议。
只使用给定数据，不要编造。明确说明这是传统命理与塔罗框架下的参考，不是专业建议。
星盘：{星盘结果}
八字：{八字结果}
本次塔罗：{塔罗结果}
历史问答：{历史问答摘要}
问题：{问题}
```

### 通用

- 页脚常驻一行免责声明：「内容属传统命理与塔罗框架，仅供娱乐与自省，不构成专业建议」
- 三路 MCP 结果都标注来源标签（星座 / 塔罗 / 八字），与 LLM 输出在视觉上分开
- 「重新分析」按钮：只重抽塔罗并重新生成洞察；星盘与八字复用首次结果
- 修改出生信息需回到输入页重新提交；提交后清空之前的星盘、八字与问答记录
