# ADR 0001 — 技术规格分层：两份 tech-spec + 项目 delta

> **已被 [0002-quanzil-single-tech-spec.md](./0002-quanzil-single-tech-spec.md) 取代。** 本文保留作历史记录。

日期：2026-10-13 · 状态：已取代

## 背景

课程示例仓库此前按「地区 × 项目」复制技术规格：Full-Stack-Templte（cn/en 各一份 300–400 行全文）+ myday（cn/hk/en 三份全文），技术栈表、性能契约、质量门槛重复 5 份。已出现事实性矛盾（cn 与 hk 的图像参考图 base64 决策相反；hk 需求的 10s 超时降级与技术规格冲突），且换 LLM/服务商、升级版本都要多点手工同步。

## 决策

1. 全仓库技术规格收敛为两份：`tech-spec.zh.md`（中国大陆+香港）与 `tech-spec.en.md`（海外）。
2. 地区/服务商差异用一张**能力矩阵**表达（能力 × 地区 → 提供方 + 陷阱 + 环境变量前缀），换服务只改矩阵一行与对应服务卡片。
3. 项目层（`projects/<name>/`）只写产品行为（req）与项目特有设计决策（tech-delta），不复制共享内容。
4. hk 繁体版本不再手工维护，用 OpenCC 从 zh 生成。
5. 版本策略：规格只记主版本 + 核对日期；patch 以课程模板 `package.json`/lockfile 为权威。

## 后果

- 维护点从 5 份全文降到 2 份全文 + 项目 delta；总量约 2550 行 → 约 1580 行。
- 换 LLM / 图像 / 地图服务 = 改能力矩阵一行 + 一张服务卡片。
- 代价：项目文档对共享契约的引用依赖文件名稳定；en 与 zh 课程的项目文档允许显式标注的教学差异（如 MyDay en 版 UI guidelines），需在文件头声明以防再次漂移。
