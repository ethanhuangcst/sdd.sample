# What2Eat — 业务需求

## 是什么

What2Eat 是一款面向「不知道吃什么」场景的 AI 辅助用餐决策助手。它根据偏好、约束、位置、天气与时段，帮助用户选出一道菜或附近一家店。它结合 Quanzil LLM、智能体（agent）、MCP 服务与地图/地点数据（高德 AMap 或 Google Maps）。它不代下单、不处理支付，也不替代餐厅菜单、过敏原标注或医学饮食建议。

## 给谁用

主要面向希望快速、带约束得到推荐的个人与小团体（「今晚吃什么？」）。公司午餐群、新城市旅客，以及饮食偏好不一致的家庭也可使用。

## 如何拼在一起

- **Web 应用** — 账户、偏好档案、「现在就定」流程、已存地点与解释视图。浏览器只与应用后端通信。
- **eat-places-mcp** — 对用户区域做地理编码，并从已批准的地图提供方（Google Maps 或高德 AMap，按 `pack/tech-spec.cn/tech-spec.md` 与 `pack/tech-spec.en/tech-spec.md` 第 1 节的地区规则）获取附近餐厅/兴趣点、营业时间与基础地点信息。
- **what2eat-agent** — 使用 MCP 数据与 RAG 知识对选项排序；区分地点事实、评估与建议。
- **food-pref-rag** — 为智能体提供菜系模式、常见饮食约束与用餐时段启发式。

## 功能

### 用户账户

- 注册新用户（姓名、邮箱、可选头像、默认城市/区域、密码）
- 使用邮箱与密码登录
- 通过邮箱重置密码
- 已登录页面右上角页头：“Hello, [Username]” + 头像 + Logout

### 偏好档案

- 采集喜欢/不喜欢的菜系、辣度耐受、预算档、默认用餐人数，以及硬约束（如素食、不吃猪肉；坚果过敏等仅作为用户自述标记）
- 保存用餐情境：工作日午餐、周末晚餐、速食、庆祝
- 可随时编辑偏好；档案上显示最近更新时间

### 现在就定

- 从当前位置（或钉选区域）+ 用餐情境 + 可选「我想吃…」文本开始
- 在营业时间可用时应用时段与「现在营业」过滤
- 返回短列表排序结果（非无限信息流）；允许在相同约束下重新洗牌
- 空结果须给出明确原因（过滤过严、附近无店、提供方故障）

### 选项卡片

- 以响应式列表或网格展示推荐地点/菜品
- 每张卡显示名称、菜系标签、可用时的距离/预计到达、价格档、营业状态、匹配理由，数据缺失时有明确占位
- 点击卡片打开地点详情；点击地图钉打开地图聚焦

### 地点详情

- 弹窗或页面展示地址、营业时间、可用时的联系方式与匹配解释；可通过关闭、Escape 或点击外部关闭
- 链接到「为什么选这个」分析；显示来源与最近更新
- 收藏或忽略需确认

### 匹配分级

- 契合度：绿（强匹配）、黄（部分匹配 / 有取舍）、红（弱匹配 / 与硬约束冲突）— 须有文字标签与说明
- 可达就绪：绿（很可能营业 / 可达）、黄（营业时间或距离不确定）、红（已关 / 不可达 / 数据缺失）— 须有文字标签与说明
- 仅靠颜色不够

### 地点 MCP — eat-places-mcp

- 内置 MCP：解析位置并获取附近用餐选项与地点详情
- 规范化提供方数据；标记过期、缺失或冲突的营业时间
- 返回标准化地点身份、距离、已知时的营业状态、来源、最近更新与置信度

### 决策提醒

- 在选项卡片与地点详情上显示警告
- 覆盖现在已关、路程过长、营业时间不完整、过敏原不确定
- 刷新后若首选变弱，须明确高亮

### 收藏与历史

- 保存喜欢的地点；对反复忽略的地点设置冷静期隐藏
- 展示近期决策：选了什么，以及用户是否标记「去了 / 跳过」
- 允许用更新后的实时地点状态重跑过去的一次决策

### 决策分析智能体 — what2eat-agent

- 使用 eat-places-mcp 与 food-pref-rag 分析候选
- 考虑偏好、约束、距离、营业状态、天气（若可用）、人数与预算
- 区分已确认的地点事实、评估与建议；不得将猜测表述为菜单或过敏原事实

### 为什么选这个

- 针对所选选项的页面：匹配理由、取舍、备选、来源、最近更新与置信度
- 可就所选地点或「附近还有什么？」对话（选择保持在会话上下文中）
- 智能体提示词存放在独立、纳入版本控制的文件中

### 群组模式

- 在同一会话中收集多名参与者的简短偏好投票
- 合并硬约束（排除项取并集）；按共同喜好排序
- 群体无法收敛时显示分歧说明

### 饮食偏好 RAG — food-pref-rag

- 知识库：菜系搭配、用餐时段启发式与常见饮食约束模式
- 应用启动时加载通用知识；进入新城市或新菜系族时按需加载本地/菜系说明
- 优先来源可靠的资料；条目在可用时应含来源与日期
- 不得将 RAG 内容当作医学或法律饮食建议

### 数据质量

- 始终显示地点信息的最近更新时间
- 标记过期、不完整、不可用或冲突的数据；区分用户偏好、地点事实与模型建议
- AI 推荐不得表述为餐厅官方承诺或健康指导
- 单一提供方故障不得拖垮整个应用

### 性能

- 附近搜索加载时立即展示已知收藏
- 满足「现在就定」、搜索、详情与 AI 响应的时延目标
- 缓存须带最近更新时间；不得将缓存的营业/关门状态标为有保证的实时状态
- 使用超时、重试与回退；避免不必要的重复 API/MCP/RAG/LLM 调用

## 成功定义

用户能一次设好偏好，快速得到少量合适选项，理解每个选择为何合适（以及哪些不确定），用自然语言追问，并准备出发——同时在下单前仍核对餐厅自己的菜单、营业时间与过敏原信息。
