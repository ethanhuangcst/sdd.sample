# Where2Play — 业务需求

## 是什么

Where2Play 是一款 AI 辅助的活动与出游去处发现工具。它根据位置、天气、可用时间、年龄段与心情，帮助人们决定去哪里玩——公园、室内游乐、运动场、亲子景点与轻松聚会点。它结合 Quanzil LLM、智能体（agent）、MCP 服务与地图/地点数据（高德 AMap 或 Google Maps）。它不代订票、不处理支付，也不替代场馆规则、安全告示或官方营业时间。

## 给谁用

主要面向带着明确约束（孩子年龄、下雨、时间短）找「附近有什么好玩」的家庭、朋友与小团体。计划散步或轻度活动的个人也可使用。

## 如何拼在一起

- **Web 应用** — 账户、游玩档案、「找点什么」流程、已存地点、出游计划与解释视图。浏览器只与应用后端通信。
- **play-places-mcp** — 对用户区域做地理编码，并从已批准的地图提供方（Google Maps 或高德 AMap，按 `pack/specs/tech-spec.*.md` 地区矩阵）获取附近场馆/兴趣点、营业时间与基础地点信息；相关时可附带当地天气。
- **where2play-agent** — 使用 MCP 数据与 RAG 知识对出游选项排序；区分地点事实、评估与建议。
- **play-context-rag** — 为智能体提供活动类型启发式、天气适宜性与年龄段说明。

## 功能

### 用户账户

- 注册新用户（姓名、邮箱、可选头像、默认城市/区域、密码）
- 使用邮箱与密码登录
- 通过邮箱重置密码
- 已登录页面右上角页头：“Hello, [Username]” + 头像 + Logout

### 游玩档案

- 采集偏好活动类型（公园、游乐场、博物馆、运动、室内软体乐园、风景散步）、精力水平、预算档，以及出行便利备注（用户自述的推车友好、无台阶等）
- 保存家庭成员年龄段（仅区间；不要求医疗数据）
- 可随时编辑档案；显示最近更新时间

### 找点什么

- 从当前位置（或钉选区域）+ 时间预算 + 天气感知开关 + 可选心情文本开始
- 在营业时间可用时应用「现在营业」/「还能开 N 分钟」过滤
- 返回地点或出游点子的短列表排序；允许在相同约束下重新洗牌
- 空结果须给出明确原因（过滤过严、纯户外遇恶劣天气、提供方故障）

### 地点卡片

- 以响应式网格或列表展示推荐地点，先按契合度再按距离排序
- 每张卡显示名称、活动标签、可用时的距离/预计到达、室内/室外、天气契合、营业状态，数据缺失时有明确占位
- 点击卡片打开地点详情；点击区域名打开区域快照

### 地点详情

- 弹窗或页面展示地址、营业时间、适宜年龄说明（启发式）与匹配解释；可通过关闭、Escape 或点击外部关闭
- 链接到「为什么选这次出游」分析；显示来源与最近更新
- 收藏或忽略需确认

### 契合分级

- 出游契合：绿（强匹配）、黄（部分匹配 / 有取舍）、红（弱匹配 / 与硬约束冲突）— 须有文字标签与说明
- 条件状态：绿（天气与营业时间看起来合适）、黄（天气勉强或营业时间不确定）、红（已关 / 恶劣天气 / 不可达）— 须有文字标签与说明
- 仅靠颜色不够

### 地点 / 条件 MCP — play-places-mcp

- 内置 MCP：解析位置并获取附近与游玩相关的地点；有用时附带当地天气摘要
- 规范化提供方数据；标记过期、缺失或冲突的营业时间
- 返回标准化地点身份、距离、已知时的室内/室外、来源、最近更新与置信度

### 出游提醒

- 在地点卡片与地点详情上显示警告
- 覆盖即将关门、户外选项的雨/热提示、营业时间不完整，以及路程相对时间预算过长
- 刷新后若首选变弱，须明确高亮

### 收藏与出游计划

- 保存喜欢的地点；可组成简单出游计划（有序停靠点 + 可选缓冲时间）
- 展示近期出游及「去了 / 跳过」反馈
- 允许用更新后的天气与营业状态重跑过去的搜索

### 出游分析智能体 — where2play-agent

- 使用 play-places-mcp 与 play-context-rag 分析候选
- 考虑活动偏好、年龄段、天气、距离、营业状态、室内/室外与时间预算
- 区分已确认的地点事实、评估与建议；不得将猜测表述为安全认证或官方年龄限制

### 为什么选这次出游

- 针对所选选项的页面：匹配理由、天气说明、取舍、附近备选、来源、最近更新与置信度
- 可就所选地点或「要是下雨呢？」对话（选择保持在会话上下文中）
- 智能体提示词存放在独立、纳入版本控制的文件中

### 区域快照

- 针对所选区域或集群的页面：游玩选项密度、天气摘要、主要约束、来源、最近更新与置信度
- 可就所选区域对话（区域保持在会话上下文中）
- 智能体提示词存放在独立、纳入版本控制的文件中

### 群组模式

- 在同一会话中收集多名参与者的简短投票：活动类型、精力、室内/室外偏好
- 合并硬约束；按共同契合度排序
- 群体无法收敛时显示分歧说明

### 游玩情境 RAG — play-context-rag

- 知识库：活动类型启发式、天气适宜性模式与年龄段出游说明
- 应用启动时加载通用知识；进入新城市或新场馆类型时按需加载本地说明
- 优先来源可靠的资料；条目在可用时应含来源与日期
- 不得将 RAG 内容当作医学、托育或法律安全建议

### 数据质量

- 始终显示地点与天气信息的最近更新时间
- 标记过期、不完整、不可用或冲突的数据；区分用户偏好、地点事实与模型建议
- AI 推荐不得表述为场馆官方承诺或安全保证
- 单一提供方故障不得拖垮整个应用

### 性能

- 附近搜索与天气加载时立即展示已知收藏
- 满足「找点什么」、详情、区域快照与 AI 响应的时延目标
- 缓存须带最近更新时间；不得将缓存的营业/关门或天气标为有保证的实时状态
- 使用超时、重试与回退；避免不必要的重复 API/MCP/RAG/LLM 调用

## 成功定义

用户能一次设好游玩偏好，快速得到少量合适的附近出游选项，理解天气与时间上的取舍及其来源与置信度，用自然语言追问，并准备出发——同时在到达前仍核对场馆自己的营业时间、规则与安全告示。
