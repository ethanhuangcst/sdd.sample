# What2Eat — 业务需求

- What2Eat 帮你在不知道吃什么时选定一家店。
- 根据你的位置、人数、已保存偏好、想吃啥、约束等，用 AI 为你推荐附近一家店。
- 界面仅中文。不使用 i18n，不预留第二语言。

## 功能

### 「数据定义」
#### 「用户」
- 用户名
- 邮箱
- 密码
- 头像
- 用户偏好档案

#### 「偏好档案」
- 喜欢的菜系
- 不喜欢的菜系
- 辣度耐受
- 默认用餐人数
- 硬约束（如素食、不吃猪肉；坚果过敏等，文字格式）

#### 「菜系」
- 首版用用户输入的文本标签。不要求维护独立菜系表
- 与高德检索对齐时，模型只输出短关键字。坐标、半径、分类码和 Key 由服务端写入，见「搜餐厅与高德反查」

### 「账号和登录」

#### 「注册新用户」
##### 「账号信息」
- 用户名（必填）。2 到 32 个字符，允许中文、字母和数字
- 邮箱（必填）。合法邮箱格式，注册后作为登录账号
- 密码（必填）。至少 8 位，须含字母和数字
- 头像（可选）。上传一张图片；未上传时用默认头像
- 默认位置（必填）。城市或区域文字，供「吃点啥？」默认填入「搜索位置」

##### 「偏好采集」
- 喜欢的菜系（多选，可选）
- 不喜欢的菜系（多选，可选）
- 辣度耐受（单选，可选）：不辣、微辣、中辣、重辣
- 默认用餐人数（可选）。正整数，默认 1
- 硬约束（多项，可选）。自由文字，如素食、不吃猪肉、坚果过敏

##### 「保存」
- 校验未通过时留在本页，标出未通过项，不写入
- 校验通过后保存用户信息与「偏好档案」
- 成功后进入「吃点啥？」

#### 「登录」
- 用户用邮箱和密码登录
- 邮箱或密码错误时，用同一句通用提示，不说明是邮箱不存在还是密码错误
- 成功后进入「吃点啥？」

#### 「忘记密码」
- 从「登录」页的「忘记密码？」链接进入「忘记密码」页
- 用户输入注册邮箱并提交后，发送重设密码邮件
- 未注册邮箱与已注册邮箱使用同一句提交成功提示，不泄露邮箱是否已注册
- 邮件里的链接打开「重设密码」页，用户设置新密码后可用新密码登录

#### 「已登录页头」
- 位于已登录页面右上角
- 从左到右：问候语「你好，{用户名}」、头像、按钮「退出」
- 点击用户名进入「修改个人信息」

#### 「修改个人信息」
- 字段与校验同「注册新用户」的「账号信息」和「偏好采集」
- 保存成功后回到「吃点啥？」，页头显示更新后的用户名与头像


### 「吃点啥？」
#### 「筛选条件」- 用户在本页面输入：
- 「搜索位置」：用户手动输入，默认使用用户偏好档案中的默认位置，必填
- 「精确匹配」/「给我惊喜」界面切换，默认为「精确匹配模式」
- 「精确匹配模式」下的筛选条件：均为非必填
    - 「用餐情境」：用户选择：办公室搭伙，单人美食，情侣约会，家庭聚餐，出门在外，快餐简食，健康减肥
    - 「用餐人数」：默认使用用户偏好档案中的默认用餐人数，可改
    - 「想吃啥？」手动多选文字框，默认展示用户偏好档案中的喜欢的菜系，可以点文字右上方叉号删除，可以输入新的文本
    - 「不选啥？」手动多选文字框，默认展示用户偏好档案中的不喜欢的菜系和硬约束，可以点文字右上方叉号删除，可以输入新的文本
- 「给我惊喜模式」
    - 点击后隐藏「精确匹配模式」下的筛选输入；切回精确匹配时保留之前填入的值
    - 本页不展示额外输入项。搜索与规则排除用的条件取自「偏好档案」，映射见下表

#### 点击「推荐餐厅」

一次推荐只走一种模式（精确匹配或给我惊喜）。精确匹配与给我惊喜共用下列三步，只换条件来源。

| 条件 | 精确匹配 | 给我惊喜 |
| --- | --- | --- |
| 想吃啥 | 本页「想吃啥？」 | 偏好档案「喜欢的菜系」 |
| 用餐情境 | 本页选择 | 空 |
| 用餐人数 | 本页（默认取档案） | 档案「默认用餐人数」 |
| 辣度耐受 | 本页（默认取档案） | 档案值 |
| 不选啥 | 本页「不选啥？」 | 档案「不喜欢的菜系」 |
| 硬约束 | 本页「不选啥？」中的硬约束项；本页未写时取档案 | 档案「硬约束」 |

##### 第一步：获得位置和时间
- 验证「搜索位置」与获得本地时间同时开始，互不等对方完成
- 位置不可用则标出，留在本页重填
- 用该位置的本地时间作为搜索时间（不写进高德检索参数）

##### 第二步：搜餐厅（至多一次模型）
- 搜索中心只用第一步的坐标。模型不输出坐标、半径或 Key
- 当「想吃啥」或「用餐情境」去掉首尾空白后任一有内容时，用上表拼好条件，调用一次「搜餐厅提示词」，得到 3 到 5 个搜索关键字
- 两者都为空时不调用模型，第三步只做基线周边检索
- 搜餐厅提示词：
```
只根据用户条件输出 JSON：{"keywords":["短关键字"]}。
条件：想吃啥、用餐情境、用餐人数、辣度耐受、不选啥、硬约束。
给出 3 到 5 个关键字。每个 2 到 10 个字，只要菜系、菜名或品牌，例如「日料」「寿司」「拉面」。
「不选啥」和硬约束排除的类别不要作为关键字。
不要返回店名、分店后缀、商场名、地址、楼层、坐标、半径、分类码或匹配理由。
不要输出其他字段。
```

##### 第三步：高德反查与规则排除
- 同一坐标、半径 10000 米、`types` 固定 `050000`（餐饮服务）。基线一次（不带关键字，始终要做）；每个关键字各一次周边检索
- 按地点 id 合并去重，合计最多 200 条。单条关键字失败则丢弃该条，其余仍合并
- 规则去掉黑名单中的店，再去掉与「不选啥」和硬约束冲突的店。过敏和忌口不由模型决定
- 列表展示的名称、地址、距离、营业状态、坐标只用高德返回字段。对照本地时间判断营业状态；无营业时间标「营业不确定」
- 空结果原因：基线无店 → 附近无店；基线有店但合并或排除后无店 → 过滤过严；基线与全部关键字检索均失败 → 提供方故障（仍展示已有收藏）

#### 「推荐餐厅列表」
- 显示在「筛选条件」下方。点击「推荐餐厅」前，本区域不显示
- 高德反查和规则排除完成后，以网格展示列表
- 每张卡片展示名称、菜系标签、距离、营业状态；缺失字段用占位说明
- 相同约束下允许重新洗牌。洗牌只换排序或抽样，不重复请求地图，不再调用模型
- 没有结果时，展示上面给出的空结果原因

#### 「地点详情」
- 弹窗展示餐厅详情。关闭、Escape 或点击遮罩可关闭
- 展示地址、营业时间、评分、价格区间、推荐菜等；字段缺失时用占位说明
- 「收藏」与「黑名单」须确认后生效


#### 「收藏与历史」

- 保存喜欢的地点；对反复忽略的地点设置冷静期隐藏
- 展示近期决策：选了什么，以及用户是否标记「去了 / 跳过」
- 允许用更新后的实时地点状态重跑过去的一次决策

#### 「黑名单」
- 用户从「地点详情」把当前餐厅加入黑名单。加入前须确认
- 每条记录保存：用户 id、高德地点 id、餐厅名称快照、加入时间。名称快照只用于列表展示，匹配以地点 id 为准
- 加入后，该店不出现在「推荐餐厅列表」和洗牌结果中。检索仍可召回该店，在规则排除阶段去掉
- 若该店已在「收藏」中，加入黑名单时同时取消收藏
- 用户可在「黑名单」页查看列表，按加入时间由新到旧。每条可移除；移除后该店可在后续推荐中再次出现
- 「黑名单」是具体店铺。「不选啥？」是会话或偏好里的文字条件，二者不互相替代

### 「数据质量」

- 始终显示地点信息的最近更新时间
- 标记过期、不完整、不可用或冲突的数据；区分用户偏好、地点事实与模型建议
- AI 推荐不得表述为餐厅官方承诺或健康指导
- 单一提供方故障不得拖垮整个应用

### 「性能」

- 附近搜索加载时立即展示已知收藏
- 满足「现在就定」、搜索、详情与 AI 响应的时延目标
- 缓存须带最近更新时间；不得将缓存的营业/关门状态标为有保证的实时状态
- 使用超时、重试与回退；避免不必要的重复 API/MCP/RAG/LLM 调用
