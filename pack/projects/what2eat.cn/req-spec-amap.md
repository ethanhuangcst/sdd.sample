# What2Eat — 业务需求

- What2Eat 是一款面向「不知道吃什么」场景的 AI 辅助用餐决策助手 web 应用
- 它根据用户当前的位置、人数、预设偏好、想吃啥、约束、天气、时段等条件，用 AI 和高德地图帮助用户选出附近一家店。


## 目标用户

主要面向“选餐困难症”的用户，希望快速、随机获得用餐推荐的个人或小团体，公司午餐群，新城市旅客，以及饮食偏好不一致的家庭。

## 功能

### 「数据定义」
#### 「用户」
- 用户名
- 邮箱
- 密码
- 头像
- 用户偏好档案

#### 「偏好档案」
- 喜欢的菜系
- 不喜欢的菜系
- 辣度耐受
- 默认用餐人数
- 硬约束（如素食、不吃猪肉；坚果过敏等，文字格式）

#### 「菜系」
- 首版用用户输入的文本标签。不要求维护独立菜系表
- 与高德检索对齐时，使用高德 POI 分类码或 `keywords`，见「获得初筛餐厅列表」

### 「账号和登录」

#### 「注册新用户」
##### 「账号信息」
- 用户名（必填）。2 到 32 个字符，允许中文、字母和数字
- 邮箱（必填）。合法邮箱格式，注册后作为登录账号
- 密码（必填）。至少 8 位，须含字母和数字
- 头像（可选）。上传一张图片；未上传时用默认头像
- 默认位置（必填）。城市或区域文字，供「吃点啥？」默认填入「搜索位置」

##### 「偏好采集」
- 喜欢的菜系（多选，可选）
- 不喜欢的菜系（多选，可选）
- 辣度耐受（单选，可选）：不辣、微辣、中辣、重辣
- 默认用餐人数（可选）。正整数，默认 1
- 硬约束（多项，可选）。自由文字，如素食、不吃猪肉、坚果过敏

##### 「保存」
- 校验未通过时留在本页，标出未通过项，不写入
- 校验通过后保存用户信息与「偏好档案」
- 成功后进入「吃点啥？」

#### 「登录」
- 用户用邮箱和密码登录
- 邮箱或密码错误时，用同一句通用提示，不说明是邮箱不存在还是密码错误
- 成功后进入「吃点啥？」

#### 「忘记密码」
- 从「登录」页的「忘记密码？」链接进入「忘记密码」页
- 用户输入注册邮箱并提交后，发送重设密码邮件
- 未注册邮箱与已注册邮箱使用同一句提交成功提示，不泄露邮箱是否已注册
- 邮件里的链接打开「重设密码」页，用户设置新密码后可用新密码登录

#### 「已登录页头」
- 位于已登录页面右上角
- 从左到右：问候语「你好，{用户名}」、头像、按钮「退出」
- 点击用户名进入「修改个人信息」

#### 「修改个人信息」
- 字段与校验同「注册新用户」的「账号信息」和「偏好采集」
- 保存成功后回到「吃点啥？」，页头显示更新后的用户名与头像


### 「吃点啥？」
#### 「筛选条件」- 用户在本页面输入：
- 「搜索位置」：用户手动输入，默认使用用户偏好档案中的默认位置，必填
- 「精确匹配」/「给我惊喜」界面切换，默认为「精确匹配模式」
- 「精确匹配模式」下的筛选条件：均为非必填
    - 「用餐情境」：用户选择：办公室搭伙，单人美食，情侣约会，家庭聚餐，出门在外，快餐简食，健康减肥
    - 「用餐人数」：默认使用用户偏好档案中的默认用餐人数，可改
    - 「想吃啥？」手动多选文字框，默认展示用户偏好档案中的喜欢的菜系，可以点文字右上方叉号删除，可以输入新的文本
    - 「不选啥？」手动多选文字框，默认展示用户偏好档案中的不喜欢的菜系和硬约束，可以点文字右上方叉号删除，可以输入新的文本
- 「给我惊喜模式」
    - 点击「给我惊喜模式」，隐藏「精确匹配模式」下的所有筛选条件
    - 切换回「精确匹配模式」时，之前填入的条件要保留
    - 「给我惊喜模式」下点击「推荐餐厅」时，本页「用餐情境」「用餐人数」「想吃啥？」视为空；仍执行基线初筛与「最佳匹配」，「最佳匹配」只用偏好档案中的硬约束
#### 点击「推荐餐厅」按钮
- 第一步：「获得位置和时间」。验证位置和获得本地时间同时开始，第二项不需要等第一项完成
    - 验证用户输入的位置是否可用。不可用就标出，留在当前页面要求重新输入
    - 用这个位置的本地时间作为搜索时间
- 第二步：获得「初筛餐厅列表」。只搜索，不展示
- 第三步：获得「最佳匹配餐厅」。只从初筛结果里选，不再请求地图

#### 获得「初筛餐厅列表」
- 用第一步得到的坐标做高德周边检索。半径固定 10000 米。坐标、半径和 Key 由服务端写入，不交给模型
- 基线检索不带关键字，`types` 固定 `050000`（高德 POI 分类码「餐饮服务」大类，只召回餐饮类 POI）。「给我惊喜」只做这一次
- 「精确匹配」且「想吃啥？」去掉首尾空白后还有内容时，再做一次关键字检索，与基线按地点 id 合并。没有「想吃啥？」时不调用模型
- 「地图参数拼装提示词」只输出 `keywords` 和 `types`
    - `keywords`：一个关键字，最长 80 字，只来自「想吃啥？」
    - `types`：只使用高德 POI 分类码，多个用 `|`。文字对不上分类码时，`types` 用 `050000`（餐饮服务），文字留在 `keywords`
- 搜索时间不写进搜索参数。对照返回的今日营业时间判断是否还在营业。没有营业时间的店标为「营业不确定」，不写成正在营业
- 同一组参数最多取 200 条
- 空结果原因：
    - 基线没有店：附近无店
    - 基线有店、合并或排除后没有店：过滤过严
    - 地图调用失败：提供方故障。这时仍展示已有收藏
- 提示词：
```
只根据「想吃啥？」输出 JSON：{"keywords":"一个关键字","types":"分类码或050000"}。
keywords 最长 80 字。types 只能使用给定分类码，多个用 |。对不上就用 050000（高德「餐饮服务」大类）。
不要输出坐标、半径、Key、营业时间或其他字段。
```

#### 获得「最佳匹配餐厅」
- 先用规则从初筛列表去掉用户「黑名单」中的店，再去掉与「不选啥？」和硬约束冲突的店。精确模式用本页的「不选啥？」。惊喜模式用偏好档案里的硬约束。过敏和忌口不交给模型决定
- 再用「推荐餐厅提示词」从剩余的店里选短列表。模型只能返回这些店的地点 id，并写匹配理由。理由标明是模型建议，不写成餐厅承诺或饮食医嘱
- 提示词的输入是：用餐情境、用餐人数、偏好档案中的辣度耐受、不选啥、硬约束，以及剩余店的地点事实。惊喜模式下，用餐情境、用餐人数和想吃啥为空
- 提示词：
```
只从给定餐厅的地点 id 中选出短列表。每条包含地点 id 和匹配理由。
匹配理由只根据用餐情境、用餐人数、辣度耐受、不选啥和硬约束，并标明是模型建议。
不要返回列表以外的店，不要编造地址、营业时间、价格或电话。
```

#### 「推荐餐厅列表」
- 显示在「筛选条件」下方。点击「推荐餐厅」前，本区域不显示
- 初筛和最佳匹配完成后，以网格展示「最佳匹配餐厅」短列表
- 每张卡片展示名称、菜系标签、距离、营业状态、匹配理由；缺失字段用占位说明
- 相同约束下允许重新洗牌。洗牌只换排序或抽样，不重复请求地图
- 没有最佳匹配时，展示初筛给出的空结果原因

#### 「地点详情」
- 弹窗展示餐厅详情。关闭、Escape 或点击遮罩可关闭
- 展示地址、营业时间、评分、价格区间、推荐菜等；字段缺失时用占位说明
- 「收藏」与「黑名单」须确认后生效


#### 「收藏与历史」

- 保存喜欢的地点；对反复忽略的地点设置冷静期隐藏
- 展示近期决策：选了什么，以及用户是否标记「去了 / 跳过」
- 允许用更新后的实时地点状态重跑过去的一次决策

#### 「黑名单」
- 用户从「地点详情」把当前餐厅加入黑名单。加入前须确认
- 每条记录保存：用户 id、高德地点 id、餐厅名称快照、加入时间。名称快照只用于列表展示，匹配以地点 id 为准
- 加入后，该店不出现在「推荐餐厅列表」和洗牌结果中。初筛仍可召回该店，在规则排除阶段去掉
- 若该店已在「收藏」中，加入黑名单时同时取消收藏
- 用户可在「黑名单」页查看列表，按加入时间由新到旧。每条可移除；移除后该店可在后续推荐中再次出现
- 「黑名单」是具体店铺。「不选啥？」是会话或偏好里的文字条件，二者不互相替代

### 「数据质量」

- 始终显示地点信息的最近更新时间
- 标记过期、不完整、不可用或冲突的数据；区分用户偏好、地点事实与模型建议
- AI 推荐不得表述为餐厅官方承诺或健康指导
- 单一提供方故障不得拖垮整个应用

### 「性能」

- 附近搜索加载时立即展示已知收藏
- 满足「现在就定」、搜索、详情与 AI 响应的时延目标
- 缓存须带最近更新时间；不得将缓存的营业/关门状态标为有保证的实时状态
- 使用超时、重试与回退；避免不必要的重复 API/MCP/RAG/LLM 调用
