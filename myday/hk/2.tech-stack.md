## 第三方能力與 API (大陸地區和香港地區通用)

### DashScope（通義千問）對話能力：`QWEN_CHAT_MODEL`

- API 配置
  - Model-name=`QWEN_CHAT_MODEL`（按項目可降級 `QWEN_CHAT_MODEL_FALLBACK`）
  - Host=`QWEN_HOST`
  - API-Key=`QWEN_API_KEY`
  - Base_URL=`QWEN_BASE_URL`
  - Workspace=`QWEN_WORKSPACE` · Region=`QWEN_REGION`
- 技術要點
  - 端點：經 `openai` SDK 調用 OpenAI 相容 `/chat/completions`
  - 參數：在 OpenAI 相容面使用 `max_completion_tokens`（**不要**用 `max_tokens`）
  - 用途：LLM 對話、JSON 生成、嵌入
  - **中國大陸 / 香港優先選用**
  - 失敗時：向調用方回傳錯誤，供組件展示錯誤並重試——禁止靜默空成功
  - 產品行為：見項目需求文件

### DashScope（通義千問）圖像能力：`QWEN_IMAGE_MODEL`

- API 配置
  - Model-name=`QWEN_IMAGE_MODEL`
  - Host=`QWEN_HOST`
  - API-Key=`QWEN_API_KEY`
  - Base_URL（原生）=`QWEN_NATIVE_BASE_URL`
- 技術要點
  - 端點：原生 `POST {QWEN_NATIVE_BASE_URL}/services/aigc/multimodal-generation/generation`（對話用 compatible-mode，不要混用；不要假設與 OpenAI `/images` 一一對應）
  - `content` 是物件陣列，每項 `{ text }` 或 `{ image }`，不要用字串 content
  - 參數：僅使用 `QWEN_IMAGE_MODEL` **API 文件已記載**的 size、quality、參考圖欄位——禁止自造尺寸或畫質檔位；size 用星號（如 `1024*1536`），不要 `x`
  - 用途：文生圖 / 圖像編輯
  - **有檔案照片時必須走帶參考圖的圖像編輯**，禁止靜默改走純文生圖：
    - `photoPath` 只存檔名；從 `data/uploads/` 讀取（`uploadsDir()`，不要 `cwd + photoPath`）
    - 伺服器端縮小參考圖（長邊約 1024px，合理 JPEG/WebP）後，須提供**公開可訪問 URL**（不能是 base64 data URL）
    - 請求 content 須同時含 `{ image: "<url>" }` 與 `{ text }`
    - 讀失敗須報錯/可重試；有照片卻不像本人：先確認讀到了檔案，再確認 content 帶了 `{ image }`
    - 成功響應：`output.choices[0].message.content[0].image` 為圖片 URL
  - **效能調優（組件目標 ≤20s；軟提示約 10s——見「效能」）：**
    - 使用任務可接受的**最低**文件尺寸與畫質——不要為「更好效果」擅自升高；不支援的參數會失敗或浪費時間
    - **每個邏輯請求一張圖**（`n: 1` 或廠商等價參數）；禁止對同一輸出並行重複調用
    - **短而結構化的提示詞**——只寫任務摘要；避免重複介面上已展示的長上下文
    - 文本已可用時，**不要**把依賴的文本 LLM 與圖像生成串在同一關鍵路徑上——先回傳文本，再盡快回傳圖像
    - 伺服器端路由：重用單一 HTTP 用戶端；出站 **HTTP 超時約 25s**（高於 20s 目標的緩衝）——**不要**另做一套 **10s 硬中止**，在 UI 仍顯示進度時把請求掐掉
    - 上游較慢時：保持請求直至超時/錯誤；用戶端約 10s 後提示「還需要更多時間」（見「效能」）——禁止把伺服器端切斷映射成「Timeout」字樣
    - 重試：每條嘗試路徑最多 **一次** 由用戶顯式觸發的重試；禁止在 20s 內自動循環重試
  - 失敗時：向調用方回傳錯誤——禁止靜默空圖
  - 產品行為：見項目需求文件

## 天氣與星座：限流與解耦

Pandorium MCP 限流嚴格。超限返回 HTTP 429，回應體**不是** JSON-RPC，而是 `{"success":false,"error":"Too many requests","retryAfter":132}`。窗口常以分鐘計。既有項目曾在測試中連打 live MCP，開發結束時上游已限流，成品無法使用。

**鏈路**

- 天氣（Open-Meteo）與星座（Pandorium）並行、互不等待；穿搭可在天氣未返回時先生成
- 前端星座請求禁止把 `weather` 放進 `useEffect` 依賴——天氣晚到會二次觸發 MCP→LLM，直接打滿配額
- 同一檔案同一日，本命盤 / 行運各最多請求一次；禁止對 429 自動重試（須等 `retryAfter` 過後再由用戶觸發）

**錯誤**

- 限流體先認 `success === false`，取出 `retryAfter` 展示給用戶
- 不要按 JSON-RPC `error.message` 解析（該欄位為 `undefined`，會變成空的「MCP 錯誤」）

**測試**

- 單元 / 整合 / CI 用夾具，禁止出網打 Pandorium
- live 冒煙兩次間隔至少 30 秒；開發過程不要把 live MCP 當日常迴歸

## 效能

圖像生成另有調優約定——見「DashScope（通義千問）圖像能力」下的效能調優。

**延遲（所有組件——僅此一套約定）：**

- 軟提示：約 **10s** 後展示「還需要更多時間」，同時繼續等待（禁止使用「Timeout」字樣）
- 目標：每個組件在 **≤20s** 內就緒
- **不要**另做一套衝突的 10s 硬超時，在無用戶可見狀態時提前放棄組件

**載入策略（所有組件）：**

- 獨立組件之間**並行**請求
- 各塊完成後即**串流 / 渲染**——不要因最慢的一塊卡住整頁
- 等待期間展示**按組件**的提示與進度

**降級：**

- 僅在上游失敗，或用戶可見等待路徑結束後組件仍為空時，使用**本地降級**
- **不要**在約 10s 時靜默切到降級，而 UI 仍暗示正在實時生成

## 實現陷阱（必須遵守）

實現時對照項目需求文件核對：

| 領域 | 約定 |
| --- | --- |
| **地區 / LLM** | 中國大陸 / 香港 OpenAI 不可用或不穩定——使用 DashScope；不要假設全球統一 LLM 主機 |
| **對話** | OpenAI 相容對話面使用 `max_completion_tokens`——**不要**用 `max_tokens` |
| **圖像（DashScope）** | 原生多模態端點；`content` 為 `{ text }` / `{ image }` 陣列；size 用 `1024*1536`；有照片必須帶公開 URL 參考圖，禁止 base64、禁止靜默文生圖；見 DashScope 圖像要點 |
| **地圖** | 單一伺服器端 `GOOGLE_MAPS_API_KEY`——禁止 `NEXT_PUBLIC_*`；中國大陸預設高德，或用 Google Maps MCP；避免從大陸直連 Google 用戶端 |
| **Tripadvisor** | 僅使用 Terra 主機；回傳 UI 前將本地化欄位展平為普通字串 |
| **AKShare MCP** | 需要本地 `uv` / `uvx`；無 API Key——不要為其偽造 Finnhub 式 token |
| **Pandorium** | 限流嚴格；天氣與星座並行；測試勿連打 live MCP——見「天氣與星座：限流與解耦」 |
| **延遲** | 軟提示約 10s · 就緒目標 ≤20s——**僅此一套約定**（見「效能」——所有組件） |
| **密鑰** | 僅通過 `.env.local` 環境變數——切勿在規格或倉庫中提交真實密鑰 |
| **儲存 / 參考圖** | `photoPath` 是 `data/uploads/` 下的檔名，不是相對倉庫根路徑；讀失敗須報錯，禁止靜默文生圖 |

## 本地化說明（i18n）

本技術棧**不受** always-on 規則中 i18n 預設需求的約束。用戶可見文案允許硬編碼；項目的本地化策略（支援語言、訊息目錄等）由該項目需求文件決定。

## 質量門檻與測試

本技術棧每個項目必須滿足的最低門檻（依據 `common-test-strategy` 基線，而非其完整預設清單）：

- 業務邏輯必須配單元測試；變更關鍵路徑 **100%** 覆蓋
- API / 數據邊界路徑配整合測試
- 至少一條關鍵用戶旅程用真實瀏覽器 E2E 覆蓋
- 測試使用臨時數據目錄——絕不用生產數據
- 無數據庫：持久化僅用 `data/` 下本地 JSON

**豁免：** 本技術棧不受 `common-test-strategy` 完整預設清單的約束；更嚴格的項目級測試策略可在各項目需求文件 / 測試策略文件中定義。
